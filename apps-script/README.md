# 마을학교 신청 백엔드 설치

이 사이트는 GitHub Pages 정적 배포(`output: "export"`)라서 서버가 없다.
그래서 마을학교 참가 신청의 저장과 관리자 조회는 **Google Apps Script 웹앱 + 스프레드시트**가 맡는다.
비용이 들지 않고, 관리자는 스프레드시트를 직접 열어 볼 수도 있다.

소요 시간 10분. 구글 계정 하나만 있으면 된다.

---

## 1. 스프레드시트 만들기

1. [sheets.new](https://sheets.new) 로 새 스프레드시트를 만든다.
2. 이름을 `망남마을학교 참가신청` 으로 바꾼다.
   (시트 탭과 헤더 행은 첫 신청이 들어올 때 스크립트가 알아서 만든다.)

## 2. 스크립트 붙이기

1. 스프레드시트에서 **확장 프로그램 → Apps Script** 를 연다.
2. 기본으로 열려 있는 `Code.gs` 내용을 모두 지우고,
   이 폴더의 [`village-school.gs`](./village-school.gs) 전체를 붙여넣는다.
3. 저장한다. (프로젝트 이름은 아무거나)

### 확장 프로그램 메뉴에 Apps Script가 없을 때

메뉴에 `부가기능`·`매크로` 는 있는데 `Apps Script` 만 없다면, 대개 셋 중 하나다.

1. **다른 구글 계정으로 시트가 만들어졌다.** 오른쪽 위 프로필 사진을 눌러 계정을 확인한다.
   개인 Gmail과 조직 계정을 함께 쓰면 자주 생긴다.
2. **구버전 메뉴를 보고 있다.** 예전에는 **도구 → 스크립트 편집기** 자리에 있었다.
3. **조직 관리자가 Apps Script를 꺼 두었다.** Google Workspace 관리 콘솔에서 끌 수 있다.

3번이면 아래 독립형 경로로 우회한다. 스크립트를 시트에 붙이지 않고 따로 만드는 방식이다.

1. [script.google.com](https://script.google.com/home) → **새 프로젝트**
2. `village-school.gs` 를 똑같이 붙여넣는다.
3. 3단계 스크립트 속성에 `ADMIN_PASSWORD` 와 함께 **`SPREADSHEET_ID`** 도 등록한다.
   값은 스프레드시트 주소에서 `/d/` 와 `/edit` 사이의 긴 문자열이다.
   ```
   https://docs.google.com/spreadsheets/d/【이 부분】/edit#gid=0
   ```
4. 나머지(4~6단계)는 동일하다.

코드는 두 방식을 모두 지원한다. 시트에 붙인 스크립트면 `SPREADSHEET_ID` 를 무시하고,
독립형이면 그 값으로 시트를 연다.

## 3. 비밀번호 설정

관리자 비밀번호는 **코드에도, 웹사이트에도 넣지 않는다.** 스크립트 속성에만 둔다.

1. Apps Script 편집기 왼쪽 **⚙ 프로젝트 설정** 으로 간다.
2. 맨 아래 **스크립트 속성 → 스크립트 속성 추가** 에서 아래를 등록한다.

| 속성 | 값 | 필수 |
|---|---|---|
| `ADMIN_PASSWORD` | 운영진이 쓸 관리자 비밀번호 | 필수 |
| `NOTIFY_EMAIL` | 신청이 들어올 때 알림 메일을 받을 주소 | 선택 |
| `SPREADSHEET_ID` | 스프레드시트 URL의 `/d/` 와 `/edit` 사이 문자열 | 독립형 스크립트일 때만 |

`SPREADSHEET_ID` 는 2단계를 **확장 프로그램 → Apps Script** 로 진행했다면 필요 없다.
아래 "확장 프로그램 메뉴에 Apps Script가 없을 때" 경로로 우회한 경우에만 등록한다.

## 4. 웹앱으로 배포

1. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱** 선택.
2. 설정을 다음과 같이 맞춘다.
   - **다음 사용자 인증 정보로 실행**: `나`
   - **액세스 권한이 있는 사용자**: `모든 사용자`
3. **배포** 를 누르고 권한 승인을 마친다.
   (첫 배포 때 "이 앱은 확인되지 않았습니다" 경고가 나오면 *고급 → 이동* 으로 진행한다.
   내가 만든 스크립트를 내 계정으로 실행하는 것이라 정상이다.)
4. 나오는 **웹 앱 URL** 을 복사한다. `https://script.google.com/macros/s/.../exec` 형태다.

> ⚠️ 코드를 고친 뒤에는 **배포 → 배포 관리 → 편집(✏️) → 버전: 새 버전 → 배포** 를 해야 반영된다.
> "새 배포"를 다시 하면 URL이 바뀌므로, 기존 배포를 편집하는 쪽을 쓴다.

## 5. 사이트에 URL 연결

레포 루트에 `.env.local` 파일을 만들고 4단계에서 복사한 URL을 넣는다.

```
NEXT_PUBLIC_VILLAGE_SCHOOL_ENDPOINT=https://script.google.com/macros/s/.../exec
```

GitHub Actions로 빌드한다면 같은 이름의 환경변수를 빌드 스텝에 추가한다.

```yaml
- run: npm run build
  env:
    NEXT_PUBLIC_VILLAGE_SCHOOL_ENDPOINT: ${{ vars.VILLAGE_SCHOOL_ENDPOINT }}
```

다시 빌드·배포하면 신청 폼이 이 URL로 저장한다.

## 6. 확인

- 신청 페이지 `/village-school/#apply` 에서 테스트로 한 건 신청해 본다.
- 스프레드시트 `신청` 시트에 행이 쌓이는지 본다.
- 관리자 페이지 `/village-school/admin/` 에서 3단계의 비밀번호로 조회되는지 본다.

---

## 보안에 대해

- **웹앱 URL은 비밀이 아니다.** 정적 사이트 번들에 그대로 실린다. 그래도 이 URL로 할 수 있는 일은 신청서를 한 건 넣는 것뿐이다.
- **조회는 비밀번호 없이는 안 된다.** `list` 요청은 스크립트 속성의 `ADMIN_PASSWORD` 와 대조한 뒤에만 응답한다. 비밀번호는 웹사이트 코드 어디에도 없고, 관리자가 그때그때 입력한 값이 서버로 전달돼 검증될 뿐이다.
- 비밀번호가 유출된 것 같으면 스크립트 속성의 값만 바꾸면 된다. 재배포도 필요 없다.
- 신청 데이터에는 건강 관련 정보가 들어간다. 스프레드시트 공유 범위를 운영진으로만 제한하고, 기획안대로 **사업 종료 후 3개월 이내에 파기**한다.

## 백엔드를 아직 연결하지 않았다면

`NEXT_PUBLIC_VILLAGE_SCHOOL_ENDPOINT` 가 비어 있으면 신청 폼은 자동으로 **내용 복사 → 문의 폼 전달** 방식으로 동작한다.
사이트가 깨지지는 않으니, 백엔드 설치를 미뤄 두고 먼저 페이지만 공개해도 된다.
